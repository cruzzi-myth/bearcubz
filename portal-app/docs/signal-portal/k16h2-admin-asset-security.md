# K1.6H.2 — Administrator asset security

Before: private upload → size/existence verification → ready; no enforceable scan evidence. After: existing request workflow → private non-ready object → size/type/SHA validation → leased scan → clean complete exact-byte evidence → explicit Approve security release → ready → existing membership-restricted signed URL. Primary-cover/artistic approval remains a separate existing control. Neither a file's name nor storage presence grants release.

Migration adds security_required/status, SHA, evidence (primary and optional thumbnail), attempt/count/lease and security-review fields to the existing collaboration_assets table. Existing rows are legacy_unverified with security_required=false; new defaults are enforced and a trigger rejects new legacy exemptions, true→false downgrades, ready without valid evidence/review, and replacing released object identity. The existing RLS upload_status condition and storage deny-by-default remain; signed URL endpoint adds an explicit security check. No duplicate asset table/system.

portal-admin-confirm-upload now scans and reports reviewRequired, leaving new assets verifying/private. portal-admin-review-asset records a separate administrator decision and only then marks ready; the database independently checks evidence. This review never changes approval_status or primary artwork. Each thumbnail needs its own evidence. The form no longer requests an unuploaded thumbnail; existing full-image fallback remains. Large thumbnails are blocked until a dedicated worker capability for that variant is implemented and verified, rather than incorrectly borrowing primary-object access.

Asset Library adds a Security column, accurate legacy/error/provider information, Scan / revalidate and Approve security release controls. Settings exposes provider configuration/health and explicitly scoped monthly observations. Existing inactive-row accessibility fix remains.

Existing nine artist objects were downloaded/hash-checked read-only. No real source asset was uploaded to Cloudmersive, replaced, deleted, deactivated or artistically approved. Both covers remain pending. The safe legacy revalidation path is implemented; original legacy scan evidence still needs recovery or explicit authorized exact-byte revalidation. No automatic legacy conversion occurred.

Development global Storage is 50MiB, independently confirmed by config pull into a temporary copy. The 100MB test exposed this infrastructure ceiling even though bucket category limit is 100MiB. Admin request and UI now reject beyond 50MiB before transfer; PORTAL_ADMIN_UPLOAD_MAX_BYTES may lower that cap but cannot silently raise it. This is distinct from the 2.9MB artist limit and from the unverified ClamAV 100MiB processing target.

Expired scan leases expose a Retry expired scan control; the real browser test reclaimed a simulated expired lease, obtained a genuine Cloudmersive result for a generated PNG, and completed explicit security release while artistic approval stayed pending. Legacy rows known to be infected are denied new signed URLs even though legacy availability is otherwise preserved. Non-ready administrator objects are outside the attachment quarantine cleanup sweep and are retained for explicit administrator reconciliation; no attachment retention policy is silently applied to them.
