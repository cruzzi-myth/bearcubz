# SIGNAL PORTAL development ClamAV worker

This is a development configuration, not deployed infrastructure. Docker, ClamD and FreshClam were unavailable on the implementation machine. No genuine ClamAV verdict or memory measurement is claimed.

1. Install a supported Docker runtime separately. Verify at least 4 GiB available to the official ClamAV container plus 512 MiB worker allowance and host headroom.
2. Copy `.env.worker.example` to gitignored `.env.worker`; generate a dedicated random >=32-character worker token out of band. Use only the authorized development project. Do not copy a service-role key into this environment.
3. Inspect `docker compose -f infra/clamav/compose.yaml config` without publishing its environment output (it can contain the token). Verify the official `clamav/clamav:1.4.6` image and digest before pulling; record the pulled digest. Support/version verified against official ClamAV docs; image pull/build was not possible here. Worker base `node:24-alpine` must also be digest-pinned in a reviewed production artifact.
4. From infra/clamav run `docker compose up --build -d`. Official image starts FreshClam and ClamD. Persistent signatures live in the named volume; do not delete it between runs. Check authenticated worker health (`SCANNER_HEALTH_URL=http://127.0.0.1:8787/health node healthcheck.mjs`) using the token from the private environment, not command-line arguments.
5. Run protocol tests from repository root: `node --test infra/clamav/tests/security.test.mjs`. These contain clearly labeled mocked protocol responses, not engine evidence.
6. Run genuine engine fixtures on a host with ClamD on loopback: `RUN_GENUINE_CLAMAV=1 node --test infra/clamav/tests/genuine.test.mjs`. Alternatively, from infra/clamav run `docker compose --profile test run --rm tests` on the isolated scanner network. Its diagnostics image includes ffmpeg; the worker runtime does not. The native harness needs ffmpeg and Python; it generates only benign fixtures and harmless EICAR. No existing artist files are sent anywhere. Without supported, fresh ClamD it reports eight skips.
7. Validate the full authenticated broker/job workflow and private TLS connectivity before dual mode is enabled. A Supabase-hosted Edge Function cannot reach a laptop's loopback worker. Do not publish ClamD or create a public tunnel as a shortcut. No worker token or larger policy was provisioned by this stage.

ClamD has no host port. Worker host publication is loopback-only 127.0.0.1:8787. The Docker network permits required FreshClam/Supabase outbound access; it is not an outbound firewall. Production requires private networking/TLS/egress allowlisting and operational ownership. Native worker defaults to loopback. One active job; no queued unbounded work. ClamD 1 thread, 60s engine limit, 100MiB stream/file, 120MiB cumulative scan, recursion 8 and max 1000 files. ZIP wrapper is stricter: 25MiB archive, 100 entries, 100MiB expansion, ratio 20, no nesting/encryption/unsupported compression. These are configured ceilings, not verified processing promises.

Record startup, signature-update/reload and scan peak memory using `docker stats --no-stream`; sample continuously during real near-limit scans and database refresh. Record CPU, elapsed time, signature version/time, image digest, actual object SHA and exact scan result. Measurements remain missing. Do not infer memory use from mem_limit.

Job temporary files use a 0700 job directory and 0600 unique payload on bounded tmpfs. No uploaded file is executed. Every path cleans up in finally; stale job directories are removed on the single worker's startup. SIGTERM drains in-flight work within the bounded job window; SIGKILL relies on restart cleanup/tmpfs lifetime. ClamAV logs omit clean object names and worker structured logs contain only attempt ID/verdict/size; do not expose raw daemon logs outside the private runtime.

Official references: [supported versions](https://docs.clamav.net/faq/faq-eol.html), [official Docker images and memory](https://docs.clamav.net/manual/Installing/Docker.html), [ClamD networking and scanning](https://docs.clamav.net/manual/Usage/Scanning.html). Official guidance recommends 3 GiB minimum / 4 GiB preferred; local usage still requires measurement.

The root .dockerignore is deny-by-default, and Dockerfile COPY statements are narrow. .env.worker, integration credentials, private media, .git and unrelated files are excluded from the build context. Secrets enter only via the private runtime env_file, never the image.
